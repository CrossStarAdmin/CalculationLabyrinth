# 04 ゲーム画面(game)

![ゲーム画面](./screen-image-design/04-game/main.png)
※画像はイメージ。

## 1. 概要
- 遺物選択と計算問題の出題を行う。ラン開始・終了時にサーバーと通信する

## 2. ユースケース
| ユースケース | アクター | トリガー | 処理 |
| ----------- | ------- | ------- | ---- |
| 遊び方を表示する | システム | ゲーム画面に遷移したとき | 遊び方画像を見せる |
| ゲームを始める | ユーザー | 遊び方画像を閉じる | 該当モードのゲームを始める |
| ゲームをポーズする | ユーザー・システム | ポーズボタンを押す・アプリがバックグラウンドに移る | ポーズ画面を表示し、再開できるようにする |
| BGMを調整する | ユーザー | 設定ボタンを押し、BGMの音量を操作する | BGMの音量を更新する |
| SEを調整する | ユーザー | 設定ボタンを押し、SEの音量を操作する | SEの音量を更新する |
| あかねが眠る | システム | 意識が0になる | 目覚めの鈴が残っていれば、使うかどうかを確認する |
| 広告をみて目覚める | ユーザー | 目覚めの鈴を使う | リワード広告を視聴後、目覚めてゲームを再開する（要件定義 2.3） |
| ラン情報を送信する | システム | ゲームが終了する | ラン結果情報をサーバーに送信する |

## 3. 画面遷移
| 操作 | 遷移先 |
| ---- | ----- |
| ゲーム終了 | 結果画面 |
| ゲーム終了（ストーリー） | ストーリー画面 |
| ポーズ画面のメニューに戻るボタンを押す | スタートメニュー画面 |

## 4. 取得要素
| 要素 | 内容 | 取得条件 |
| --- | --- | --- |
| ランID | ランを識別するID | ラン開始情報の送信後 |
| シード | 問題・遺物・ガーディアンの生成に使う乱数の種 | ラン開始情報の送信後 |

## 5. 送信要素
| 要素 | 内容 | 送信条件 |
| ---- | ---- | ------- |
| ラン開始情報 | モード・難易度・プレイ形式 | ゲームを始める前 |
| ラン結果情報 | 各問の正誤と残り時間、選んだ遺物、申告スコア | ゲームが終了した後 |
| 解放するガーディアン情報 | そのランで初めて出会ったガーディアン | ゲームが終了した後 |
| 解放する遺物情報 | そのランで初めて出会った遺物 | ゲームが終了した後 |

## 6. 例外処理
| 条件 | システムの対応 |
| ---- | ------------ |
| ラン開始情報を送れない | エラーモーダルに「ゲームを開始できません。」と表示。スタートメニューに戻るボタンと再接続ボタンを表示 |
| ラン結果情報を送れない | エラーモーダルに「スコアを送信できませんでした。」と表示。スタートメニューに戻るボタンと再接続ボタンを表示。戻る場合はスコアが保存されないことを警告する |

## 7. 細かな仕様

### ラン開始とスコア検証
サーバーが発行したシードから、クライアントとサーバーが同じランを再現する。問題・遺物のデータは送受信しない。

- サーバーはラン開始情報を受け取ると、ランID・シードを返し、ランID・シード・開始時刻を保存する
- クライアントはシードから問題・遺物の候補・ガーディアンをローカルで生成する
- サーバーはラン結果情報を受け取ると、シードからランを再現してスコアを再計算し、申告スコアと照合する
- 以下は不正とみなす: スコア不一致 / 残り時間が制限時間を超える / 問題数が合わない / 開始から終了までの実時間が短すぎる

### ゲームの進行
- 遺物選択（提示された3つから1つ選ぶ）→ 計算（ガーディアンが出す20問を解く）を繰り返す
- ゲームの細かな仕様は別資料で定義する

### ポーズ・中断
- バックグラウンドに移ったらポーズする
- ポーズ中は制限時間を止め、問題を隠す
- アプリが終了したらランのデータをすべて破棄する
